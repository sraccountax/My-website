# R20 changes and evidence boundary

**Implemented candidate; no authenticated host/MariaDB/SMTP release certification.**

## P&L

Authoritative company-scoped posted GL aggregation by calendar month and comparison period. Current totals, prior-period totals, signed variance and percentage variance are available for accounts, sections and net profit. Comparison choices are none, same dates last year, previous equal-length period and custom dates. Partial calendar months are clipped; no annualization/proration is invented. Prior-only/inactive historical accounts and offsetting month movements are retained. Percentage = (current − prior) / absolute(prior); nonzero against zero is N/A, and two zeros are 0%.

The existing posted-ledger accounting basis and base currency remain authoritative. No cash/accrual conversion or cross-currency consolidation is introduced. Select one company for comparison. Desktop fits a readable window of month columns with Previous/Next buttons; all months remain available. Narrow layouts use vertically stacked account details. PDF/print use complete comparison/month panels; Excel includes all selected month columns regardless of the screen window. Changed filters invalidate old output until Run report.

## Invoice Edit

Uses existing invoice-write permission, scoped row locks, an optimistic revision and an idempotency receipt. Unissued non-opening drafts allow customer/date/currency, line descriptions, quantities, prices, tax and income-account edits; validation/recalculation uses the shared original invoice preparation routine. Existing import/recurring identity is retained. Draft changes update the saved voucher but do not post a journal.

Issued invoices permit due date, purchase order and message changes only. Posted amounts/customer/currency/date require the existing accounting-correction workflow rather than silent mutation. Void invoices and locked periods are protected. Unsaved and conflicting edits remain in the form. Pending email intents block edit/issue/void, including the Transaction Void route.

## Invoice Send

Real backend submission path through the existing mail service: recipient/subject/message, optional supporting files, server-rendered preview, explicit confirmation, durable receipt, transport result and Delivery history. No automatic send from opening the form or generating a preview. Same operation/payload replays its result instead of sending twice. Ambiguous or interrupted outcomes need review and are never automatically resent.

**The full invoice is embedded in the email body.** Only selected supporting files are attached, up to 2 MiB combined. There is no automatic invoice-PDF attachment. Existing Download PDF remains; users can upload/select that PDF explicitly. Drafts must first be issued through the original workflow. An outgoing-service acceptance is not an inbox-delivery guarantee. Actual configured SMTP and controlled-inbox receipt were not tested here.

## Invoice Attachments

Private native multipart upload, authorized download, visible metadata and audited soft removal. PDF, PNG, JPEG and WebP only; extension/MIME/signature checks, 10 MiB per file, 20 active files, 100 MiB retained evidence per invoice, 40 megapixels for images. Random private paths, file SHA-256 integrity checks and restricted file modes. Attachments are not implicitly emailed. Removed files remain retained evidence but cannot be downloaded through the active attachment route. These controls do not constitute malware scanning or content disarm.

## Storage and upgrade

Schema 46 adds operation/attachment metadata with company/invoice/actor relations and idempotency/index contracts. Protected owner preflight/upgrade, previous migration-receipt checks, backup/restore maps and child-first company deletion are updated. Existing payroll/opening-balance named source files remain byte-identical to R19. No R20 payroll formula or opening-balance behavior was changed. See `UPGRADE-SCHEMA-46-R20.md`.
